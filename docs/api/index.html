This page is generated from an OpenAPI 3.1 document. It covers 22 operations across 17 public paths. Paths are discovered from the running application; only the /api/v1 resources have stable, documented response schemas.

Authentication

Every public endpoint requires an authenticated session or API key, except the documentation page itself. Unauthenticated requests receive 401 with {"code": "unauthorized"}. Requests are authorized with the same ownership and workspace-role checks as the web UI.

Pagination

List endpoints accept page (1-based) and limit (default 50, maximum 100) and return:

{"items": [], "total": 0, "page": 1, "limit": 50, "next_cursor": null}

Oversized limits are clamped; malformed values return a structured 400 invalid_input error. See docs/pagination.md for the full contract.

Errors

Errors use one stable JSON shape:

{"error": "The request is invalid.", "kind": "invalid",
"code": "invalid_input"}

Treat code as the contract. The catalog lives in app/api/error_catalog.py; docs/api-errors.md lists every code and HTTP status. Internal exception text is never exposed.

Webhook verification

Webhook deliveries are signed over the exact raw bytes sent: <timestamp>.<body>, using HMAC-SHA256 with the subscription secret. Verify the X-AICA-Signature: v1=<hex> header against X-AICA-Timestamp with a constant-time comparison and reject timestamps outside the 300-second tolerance window. Verify the raw body before parsing or re-encoding JSON. See docs/webhooks.md.
