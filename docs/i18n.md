# Internationalization (i18n)

The app ships a small, dependency-free translation layer (#714).

## Catalogs

User-facing strings live in `app/translations/<locale>.json`:

```json
{
  "nav.home": "Home"
}
```

- `en` is the source locale and the fallback.
- `ar` is the representative right-to-left locale.
- A missing key falls back to English, then to the key itself, so partial
  translations never render blank.

## Selecting a locale

The active locale is resolved from, in order:

1. `?lang=<locale>`
2. the `locale` session value (set by `/i18n/locale/<locale>`)
3. `Accept-Language`
4. English

The shared navigation exposes a locale switcher. `<html>` receives the matching
`lang` and `dir` attributes, and RTL pages load `css/rtl.css`.

## Templates and JavaScript

- Templates use `{{ t('key') }}`.
- The active catalog is embedded once in `<script id="i18n-catalog">`.
- `static/js/i18n.js` reads that catalog and exposes `window.AICA_I18N.t(key)`.
  Templates and JavaScript therefore share one string table.

## Extraction and checks

`scripts/extract_i18n_strings.py` scans templates for `t('...')` keys and reports
keys that are missing from a catalog or unused:

```bash
python scripts/extract_i18n_strings.py
```

`tests/test_i18n.py` asserts catalog parity, fallback behavior, RTL output, and
that the extraction script is clean.

process, glossary, and review checklist.
