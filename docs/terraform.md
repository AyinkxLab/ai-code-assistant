# Terraform: managed database and app runtime (#708)

The module in [`deploy/terraform/`](../deploy/terraform/) provisions a private
PostgreSQL 16 database and an ECS Fargate runtime for the web process and the
job-queue worker. It is deliberately small: networking already exists, and
ingress/load balancing is left to the platform you run.

The module is validated statically by `tests/test_deploy_terraform.py` because
`terraform` is not part of the Python toolchain. **`terraform validate` has not
been run in this repository's test environment.** Run it yourself before the
first apply:

```bash
cd deploy/terraform
terraform init -backend=false
terraform validate
```

## Inputs

| Input | Default | Notes |
| --- | --- | --- |
| `aws_region` | `us-east-1` | Validated against the AWS region pattern. |
| `name_prefix` | `aica` | 2-31 lowercase alphanumeric/hyphen characters. |
| `vpc_id` | required | Must be an existing `vpc-...` id. |
| `private_subnet_ids` | required | At least two `subnet-...` ids. |
| `allowed_ingress_cidrs` | `["10.0.0.0/8"]` | CIDRs allowed to reach the container port. |
| `db_instance_class` | `db.t4g.medium` | RDS instance class. |
| `db_allocated_storage` | `100` | 20-16384 GiB. |
| `db_name` / `db_username` | `aica` / `aica` | Lowercase identifiers only. |
| `db_multi_az` | `true` | Synchronous standby in a second AZ. |
| `db_backup_retention_days` | `7` | 0-35 days. |
| `app_image` | required | Tagged image reference, e.g. `ghcr.io/org/ai-code-assistant:0.1.0`. |
| `app_secret_key_secret_arn` | required | Secrets Manager ARN for Flask `SECRET_KEY`. |
| `database_url_secret_arn` | required | Secrets Manager ARN for the full SQLAlchemy URL. |
| `app_cpu` | `512` | 256, 512, 1024, 2048 or 4096. |
| `app_memory` | `1024` | 512-8192 MiB. |
| `app_container_port` | `5000` | 1-65535. |
| `web_desired_count` | `2` | 1-50. |
| `worker_desired_count` | `1` | 0-50; zero disables the worker. |
| `log_retention_days` | `30` | CloudWatch-supported retention value. |

Every input has a `validation` block with an `error_message`. Terraform reports
invalid values as structured diagnostics before any resource is created, so a
bad CIDR, region or secret ARN fails the plan rather than the deployment.

## Credentials

- The database password is generated by RDS (`manage_master_user_password =
  true`). It never appears in this module, state, or logs.
- The task execution role may call `secretsmanager:GetSecretValue` on exactly
  the two ARNs supplied. Nothing else.
- Create the secrets out of band:

  ```bash
  aws secretsmanager create-secret --name aica/secret-key \
    --secret-string "$(python -c 'import secrets; print(secrets.token_hex(32))')"
  aws secretsmanager create-secret --name aica/database-url \
    --secret-string "postgresql://aica:<password>@<endpoint>:5432/aica"
  ```

  Build `DATABASE_URL` from the RDS password secret after the first apply, or
  store the URL with a dynamic reference: this module does not copy secrets
  between services.

## Permissions

The identity running `terraform apply` needs, at minimum:

- `ec2:*SecurityGroup*`, `ec2:DescribeVpcs`, `ec2:DescribeSubnets`
- `rds:CreateDBInstance`, `rds:ModifyDBInstance`, `rds:DescribeDBInstances`,
  `rds:CreateDBSubnetGroup`, `rds:AddTagsToResource`
- `ecs:*Cluster*`, `ecs:*Service*`, `ecs:*TaskDefinition*`,
  `ecs:Describe*`, `ecs:List*`
- `iam:CreateRole`, `iam:PutRolePolicy`, `iam:AttachRolePolicy`,
  `iam:PassRole`, `iam:GetRole`
- `logs:CreateLogGroup`, `logs:PutRetentionPolicy`, `logs:DescribeLogGroups`
- `secretsmanager:DescribeSecret` on the two secret ARNs

A permission failure is returned by the AWS provider as an API error during
plan/apply; the caller sees the failing action and ARN. This module does not
broaden permissions to work around that.

## Operating notes

- Tasks run in private subnets with `assign_public_ip = false`. They need a NAT
  gateway or VPC endpoints for ECR, S3, CloudWatch Logs and Secrets Manager.
- Run migrations as a one-off task before rolling the web service:
  `flask db upgrade`. The module does not put migrations in the container
  entrypoint, so several replicas cannot race (see
  [Safe migration rollout](migration-rollout.md)).
- The database is not publicly accessible. Reach it through a bastion or SSM
  session, not by changing `publicly_accessible`.
- Add an ALB/ingress in front of the `web` service; this module does not create
  one.
- `deletion_protection` and `skip_final_snapshot = false` are on. Removing the
  database requires an explicit two-step change.

## Tests

`tests/test_deploy_terraform.py` asserts required variables, defaults, every
validation block and its message, outputs, region wiring, example usage, secrets
manager access, and that no inline password exists. It does not validate HCL
syntax.
